GTM（Googleタグマネージャー）でタグを設定して、プレビューでは発火している。それなのに、広告の管理画面では成果がゼロだったり、GA4の購入数が実際の注文の2倍になっていたりする。計測の相談を受けると、原因の多くは設定の細かい漏れです。

この記事では、私が実務で繰り返し見てきた設定ミスを16個にまとめました。それぞれ「どう確認すればよいか」と「よくあるNG例」をセットで書いています。

選んだ媒体とイベントに合わせて確認項目を出せる無料ツール [GTMタグ設定チェックリスト生成](/tools/gtm-checklist/) も用意したので、設定のたびに使ってみてください。

[![GTMの確認は設定前・設定中・公開前・公開後の4段階に分けると漏れにくい](/images/blog/gtm-tag-setup-mistakes/four-stages.svg)](/images/blog/gtm-tag-setup-mistakes/four-stages.svg)

## タグ・トリガーのミス

### 1. 同じイベントが複数回発火して、成果が二重に計上される

1回の送信や購入で、成果タグが2回発火しているケースです。トリガーが2つ設定されている、似たタグが2つある、などが原因です。

- **確認方法**：GTMのプレビューモードで操作を1回だけ行い、対象のタグが1回だけ発火しているか見る
- **NG例**：1回の送信で、Google広告のコンバージョンタグが2回発火している

### 2. ボタンのクリックだけで成果を計測している

問い合わせボタンのクリックをトリガーにすると、入力エラーで送信できなかった人まで成果に入ります。成果は「送信が成功したこと」で計測します。

[![クリックで計測すると入力エラーの人も成果に入る。送信成功で計測する](/images/blog/gtm-tag-setup-mistakes/click-vs-submit.svg)](/images/blog/gtm-tag-setup-mistakes/click-vs-submit.svg)

- **確認方法**：送信成功時に dataLayer.push されるイベント、または完了ページのURLがトリガーになっているか見る
- **NG例**：必須項目が空のまま送信ボタンを押しただけで、成果が計上される

### 3. トリガーの条件が広すぎて、関係ないページでも発火する

成果タグのトリガーが「All Pages」のままになっている、URLの条件が「含む」で広すぎる、といったケースです。

- **確認方法**：対象ページと対象外のページを両方プレビューで開き、対象でだけ発火するか見る
- **NG例**：トップページを開いただけで成果タグが発火する

### 4. GTMとサイトへの直接埋め込みで、同じタグが重複する

以前の担当者がサイトに直接書いたタグが残ったまま、GTMでも同じタグを入れてしまうケースです。ページビューも成果も2倍になります。

[![直書きのgtag.jsとGTMのGA4タグが両方あるとpage_viewが2回送られる。GTMに一本化すると1回](/images/blog/gtm-tag-setup-mistakes/duplicate-tags.svg)](/images/blog/gtm-tag-setup-mistakes/duplicate-tags.svg)

- **確認方法**：Tag Assistantでページを開き、同じ測定IDやピクセルIDのタグが2つ検出されていないか見る
- **NG例**：GA4の page_view が1回の表示で2回送られている

### 5. SPAの画面遷移でページビューが正しく計測されない

React や Vue で作られたSPAは、画面が切り替わってもページを読み込み直しません。何もしないと最初の1ページしか計測されず、逆に2つの方法で計測すると2重になります。

Googleの公式ガイドでは、GTMで計測する場合、GA4の拡張計測の「ブラウザの履歴イベントに基づくページの変更」をオフにして、GTMの履歴の変更トリガーで page_view を送る方法が紹介されています（[Google for Developers](https://developers.google.com/analytics/devguides/collection/ga4/measure-spa-gtm)）。

- **確認方法**：プレビューとGA4のDebugViewで画面を何回か移動し、遷移ごとに page_view が1回ずつ送られているか見る
- **NG例**：拡張計測をオンのままGTMでも送り、画面遷移ごとに page_view が2回送られる

## パラメータ・データのミス

### 6. 購入金額が文字列のまま送られる

GA4のリファレンスでは、purchase の value は数値（number）と定義されています（[Google for Developers](https://developers.google.com/gtagjs/reference/ga4-events)）。"5000" や "5,000円" のような文字列で送られていると、収益が正しく集計されない原因になります。

- **確認方法**：GA4のDebugViewで購入イベントを開き、value の値と型を見る
- **NG例**：value が "5000"（ダブルクォートつき）で送られている

### 7. value・currency・transaction_id が設定されていない

GA4では、value を送るときは currency も必須です。transaction_id は購入の重複を防ぐためのパラメータです（[Google for Developers](https://developers.google.com/gtagjs/reference/ga4-events)）。Google広告のコンバージョンタグも、取引IDを設定すると同じ取引IDの成果を重複として除外します（[Google 広告 ヘルプ](https://support.google.com/google-ads/answer/6386790)）。

- **確認方法**：DebugViewやTag Assistantで、3つの値がそろって送られているか見る
- **NG例**：value だけ送って currency がない。取引IDの欄に固定の文字列を入れていて、2件目以降の成果がすべて重複扱いになる

### 8. dataLayerの変数名とGTM側の変数名が一致していない

サイトは `transactionId`、GTMの変数は `transaction_id` を読みにいく、といったずれです。値は undefined になり、エラーも出ないので気づきにくいミスです。

[![dataLayerのキー名とGTMのデータレイヤー変数名が一致しないとundefinedになる](/images/blog/gtm-tag-setup-mistakes/datalayer-variables.svg)](/images/blog/gtm-tag-setup-mistakes/datalayer-variables.svg)

- **確認方法**：プレビューの「Variables」タブで、変数に値が入っているか見る
- **NG例**：`ecommerce.value` に入っている値を `value` で参照して、undefined になる

### 9. 購入完了ページの再読み込みで、購入イベントが再送される

完了ページを再読み込みしたり、ブラウザの「戻る→進む」で再表示したりするたびに、購入イベントが送られるケースです。

- **確認方法**：完了ページで再読み込みし、購入タグが再び発火しないか見る。発火する場合は、開発側で1回だけ送る仕組みにするか、transaction_id で重複を除く
- **NG例**：お客様が完了ページを再読み込みするたびに、売上が増えていく

### 10. Meta Pixel と Conversions API でイベントIDが一致していない

Pixel（ブラウザ）と Conversions API（サーバー）の両方からイベントを送る場合、Metaは**イベントIDとイベント名の両方が一致**したものを重複として1件にまとめます。重複の除外は、最初のイベントを受け取ってから48時間以内に届いたものが対象です（[Meta for Developers](https://developers.facebook.com/docs/marketing-api/conversions-api/deduplicate-pixel-and-server-events)）。

[![PixelとConversions APIでイベントIDとイベント名が一致すれば1件、IDが違うと2件として計上される](/images/blog/gtm-tag-setup-mistakes/meta-dedup.svg)](/images/blog/gtm-tag-setup-mistakes/meta-dedup.svg)

- **確認方法**：イベントマネージャでブラウザとサーバーの両方のイベントが届き、重複が除かれているか見る
- **NG例**：Pixel はランダムなID、サーバーは注文番号を event_id に使い、同じ購入が2件になる

## 媒体・公開設定のミス

### 11. Google広告のコンバージョンIDとラベルを取り違える

Google広告のコンバージョンタグは、コンバージョンIDとコンバージョンラベルの組み合わせで、どのアクションに計上するかが決まります。購入用と問い合わせ用のラベルを取り違えると、別のアクションに成果が入ります。

- **確認方法**：Google広告の「目標」の概要からTag Assistantを開き、対象のアクションに成果が届くか見る（[Google 広告 ヘルプ](https://support.google.com/google-ads/answer/10989978)）
- **NG例**：問い合わせの成果が、購入のコンバージョンアクションに計上されている

### 12. GA4の測定IDを別プロパティのものにしている

テスト用のプロパティや旧サイトのプロパティの測定IDを入れてしまうケースです。GTMでは問題なく発火するので、見落とされがちです。

- **確認方法**：GA4の管理画面で、計測したいプロパティの「データストリーム」にある測定IDと一致しているか見る
- **NG例**：本番サイトのデータが、テスト用プロパティに送られている

### 13. 同意管理の設定が不適切で、同意に応じたタグの制御ができていない

同意管理ツール（CMP）を入れていても、GTM側の設定が合っていないと、同意を拒否したユーザーにも広告タグが動きます。GTMでは、CMPのタグを「同意の初期化」トリガーで動かし、各タグの同意設定を入れます。コンテナ設定で「同意の概要」を有効にすると、全タグの同意設定を一覧で確認できます（[タグ マネージャー ヘルプ](https://support.google.com/tagmanager/answer/10718549)）。

- **確認方法**：同意を拒否した状態でプレビューし、対応するタグが止まるか見る
- **NG例**：CMPのタグが通常の All Pages で動き、広告タグが同意の反映より先に発火する

### 14. プレビューでは動くのに、本番に公開されていない

GTMの変更は、公開するまでサイトには反映されません（[タグ マネージャー ヘルプ](https://support.google.com/tagmanager/answer/2699097)）。プレビューで動いたことに満足して、公開を忘れるケースは意外と多いです。

- **確認方法**：GTMのバージョン一覧で、今回の変更を含むバージョンが公開中になっているか見る
- **NG例**：設定から1週間たっても成果がゼロで、調べたら公開されていなかった

### 15. GTMで発火しただけで、広告媒体側の受信を確認していない

GTMのプレビューで分かるのは「タグが発火したか」までです。媒体にデータが届いているかは、各媒体の管理画面で確認します。

- **確認方法**：GA4はリアルタイムレポート、Google広告はコンバージョンアクションのステータス、Metaはイベントマネージャ、LINE広告は「トラッキング（LINE Tag）」のステータスを見る
- **NG例**：GTMでは成功しているのに、媒体側では受信されていない

### 16. テスト購入や社内アクセスが、本番の成果に混ざる

設定を確認するためのテスト購入や、社内・関係者のアクセスが、そのまま本番の数字に残るケースです。GA4では、IPアドレスで内部トラフィックを定義し、データフィルタで除外できます。フィルタは「テスト」状態で確認してから「有効」にします。有効にすると除外したデータは元に戻せないので注意が必要です（[アナリティクス ヘルプ](https://support.google.com/analytics/answer/10104470)）。

- **確認方法**：テストで発生した注文番号を記録しておき、数日後に管理画面の件数と計測の件数を突き合わせる
- **NG例**：公開初日の売上の半分が、社内のテスト購入だった

## 設定のたびにチェックリストで確認する

16個のミスは、どれも一つひとつは小さなものです。ただ、設定のたびに全部を思い出すのは大変です。

[GTMタグ設定チェックリスト生成](/tools/gtm-checklist/) では、使う媒体とイベントを選ぶと、ここで紹介した内容を「設定前・設定中・公開前・公開後」の4段階に分けて出します。チェックの状態はブラウザに保存され、Markdownでコピーして案件のタスク管理に貼ることもできます。

*記事内の仕様は2026年10月26日時点の各公式ドキュメントで確認しています。管理画面の名称や仕様は変わることがあるので、設定時は各公式ヘルプもあわせて確認してください。*
